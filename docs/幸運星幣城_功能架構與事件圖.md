**讀圖三個關鍵約定：**

1. **指令 vs 事件（ADR-002）**：`wallet.credit.request` 是「請幫我入帳」的**指令**，只有 wallet 消費；
   `wallet.credit`／`wallet.debit` 是「已入帳／已扣款」的**事件**。發指令的服務（member／admin／game）
   一律不自己寫 wallet。
2. **不可迴圈（雷區 6）**：消費 `wallet.credit`／`wallet.debit` 的 listener 絕不可回頭呼叫
   `credit()`／`debit()`。唯一安全例外是 `WalletReadSyncListener` — 它只寫 MySQL 讀視圖並做
   `existsById` 冪等檢查。
3. **消費端去重看操作是否冪等（藍圖 04 P1）**：`ZADD` 絕對值＝冪等，**不可**加去重；
   `ZINCRBY` 累加＝非冪等，需用 `transactionId` 做 Redis `SETNX`。Notification 為 best-effort，
   刻意**不設 DLT**；`member.registered.DLT`／`friend.relationship.updated.DLT` 目前只建 topic、
   尚無 listener 落地。

```mermaid
    W->>PG: 同交易寫 wallet_outbox（wallet.debit）
    W-->>G: 扣款成功
    G->>G: Provably Fair RNG：SHA-256(serverSeed:clientSeed:nonce)
    G->>W: POST /internal/wallet/credit（命中才呼叫）
    alt credit 失敗
        G->>PG: 落 pending_wallet_credits，排程 30s 用同一冪等鍵重試（ADR-009）
    end
    G->>PG: 寫 game_rounds、風控釋放 Lua
    G->>K: publish game.result
    G-->>FE: 200 遊戲結果
    W->>K: Outbox poller 送出 wallet.debit / wallet.credit
    K->>MY: WalletReadSyncListener 同步讀視圖
    K->>R: 更新 rank:global:coins / rank:daily:winnings
    R->>K: publish rank.update
    K->>N: game.result / rank.update
    N-->>FE: STOMP 推播（/user/queue/notifications、/topic/rank）
```
