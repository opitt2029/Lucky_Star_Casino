04這張圖是怎麼畫出來的

  1. 先把身分收斂

    原始歷史裡有 8 組 name/email，直接跑 git shortlog 會把同一個人算成好幾位。專案根目錄的 .mailmap 把它們映射到同一個正式姓名，git 自己就會合併 —— 不需要 rebase 改寫歷史（分支已共享，改寫會炸掉所有人的本機）。

  2. 取數：只數 commit，排除 merge

    merge commit 不含實際改動，算進去會讓負責合併的人虛胖。--no-merges 排掉。

  3. 選一個分支當分母

    用 develop（整合分支）。main 是 squash 過的，只剩 22 筆，拿來當分母會失真。

  4. 四個人的顏色先綁死

    顏色代表「人」不代表「名次」。若照排名上色，換一張圖名次一變顏色就跟著換，讀者會誤以為是不同人。

  5. 輸出成向量 SVG

    PPT 可以直接插入 SVG，投影放大不糊，插入後還能在 PPT 內按右鍵「轉換成圖形」改字改色。

05怎麼放進 PPT

  • 插入 → 圖片 → 此裝置，選 docs/report/contribution/pie-*.svg。PowerPoint 2016 以後原生支援 SVG。
  • 圖已經自帶標題、副標與資料來源，整張貼滿一頁投影片就是完整的一頁，不必再另外打字。若你的版型已有標題列，插入後裁掉上方標題區即可。
  • 要改字體或配色：在 PPT 裡對圖按右鍵 → 轉換成圖形，之後每個文字與色塊都能單獨編輯。
  • 四張分面圖尺寸一致（440×326），並排成 2×2 剛好是一頁。
  • 若簡報主題是深色底：這些圖是白底的，建議放在白色卡片上，不要直接透明疊在深色背景。

06誠實的限制

commit 數不等於工作量。習慣小步提交的人數字天生比較高；把一整天的工作壓成一筆的人會被低估。這張圖適合呈現「參與的廣度與節奏」，不適合當作績效評分。

那為什麼不用「程式碼行數」？試算過了，用行數會更失真：本專案行數前兩名的差距，幾乎完全來自 docs/performance/assets/ 底下約 3.5 萬行機器產生的壓測 CSV，以及 1.3 萬行 package-lock.json。那些不是人寫的程式碼。相較之下，commit 數至少每一筆都對應一次真實的「做完一件事並提交」。

要更貼近實際分工，建議簡報時把這張圖跟 工作分配表（T-000～T-114） 並列：圖說明節奏，任務表說明範圍。
