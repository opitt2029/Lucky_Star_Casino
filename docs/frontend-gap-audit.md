# Frontend Gap Audit

- Repository: `opitt2029/Lucky_Star_Casino`
- Branch inspected: local `develop` workspace
- Scope: `frontend/` player application, with supporting contracts and docs only where they explain frontend behavior
- Audit date: 2026-07-27
- Stack observed: React 18, Vite, Redux Toolkit, React Router, Tailwind CSS, PixiJS, STOMP over SockJS

## Executive Summary

The player frontend is no longer a thin shell: core routes exist, the three wagered games are playable, wallet/check-in/shop/diamond/friends/profile/rank/records flows are wired, and there is meaningful test coverage around API refresh, mock parity, slot visual lock, fishing controls, fullscreen layout, and smoke/e2e paths.

The remaining gaps are concentrated in four places:

1. Inventory is still a display-and-placeholder flow; redeemed items cannot actually be equipped, consumed, or reflected in profile/site appearance.
2. Records uses a 200-row client merge instead of real server-backed pagination/export and omits several fields a player would expect for game/account review.
3. Real-time behavior is guarded by environment flags and defaults to mock when mock API is enabled, so true WebSocket behavior is easy to miss outside the dedicated realws e2e path.
4. Several dialogs/dropdowns are visually complete but need stronger focus management and keyboard behavior before they are production-polished.

This audit also records frontend work completed in this pass: dedicated game-card SVG assets, global announcement host outside `PageTransition`, readable route fallback text, and a real Not Found route.

## Validation Matrix To Run

| Command                             | Purpose                                                                            |
| ----------------------------------- | ---------------------------------------------------------------------------------- |
| `cd frontend && npm run lint`       | Catch JSX/import/CSS-adjacent lint issues after route and host changes.            |
| `cd frontend && npm run test`       | Validate unit tests for API refresh, mocks, slot/fishing components, and fairness. |
| `cd frontend && npm run build`      | Confirm Vite resolves new SVG assets and lazy routes.                              |
| `cd frontend && npm run e2e`        | Validate smoke, site settings, fishing, fullscreen, and realtime mock paths.       |
